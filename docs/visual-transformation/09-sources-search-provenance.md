# 09 — خزانة المصادر والبحث والعزو
## عقد الثقة المشترك بين القرآن والسيرة والحديث والمكتبة والأطلس

**المسار المعلن في الهوية:** /sources.  
**الحالة الفعلية الحالية:** /sources يفتح SunnahPage، ولذلك الخزانة المستقلة غير منفذة بعد بوصفها جناحًا منفصلًا.  
**المكونات المرجعية:** SourceDrawer وEvidenceDrawer وGlobalSearchDialog وما يرتبط بها من نماذج بيانات.  
**خط الأساس المقروء:** 617f656008c95884dcc755144dfeadaeda24a352.  
**المرجع الملزم:** العقد 00 والغلاف 02، مع تطبيق هذا العقد على الوثائق 03–08 وسائر الصفحات المساندة.  
**الحالة:** مواصفة تنفيذ وثقة؛ لا تمنح أي سجل صفة «محقق» لمجرد ظهوره داخل الواجهة.

## 1. لماذا هذه الخزانة جناح مستقل

خزانة المصادر هي طبقة الثقة في المؤسسة كلها. وظيفتها ليست وضع Badge أخضر بجوار النص، بل تمكين القارئ من معرفة: ما المصدر؟ أين موضعه؟ ما النسخة أو الطبعة المتاحة؟ ما الذي نُقل فعلًا؟ ما الذي ما زال قيد المراجعة؟ وما حدود اليقين في الادعاء؟

يجب أن تعمل الخزانة مع القرآن والسيرة والحديث والمكتبة والأطلس والأطفال واليومي، دون أن تفرض نموذجًا واحدًا يحشر أنواع الأدلة المختلفة في حقول غير مناسبة.

المستخدم لا يحتاج درسًا في قواعد البيانات. يحتاج جوابًا صريحًا على سؤال بسيط: **لماذا أرى هذه المعلومة، وما سندها داخل المنتج؟**

## 2. الواقع الذي يجب تصحيحه

القراءة الساكنة للحالة الحالية تكشف مشكلات عالية الأهمية:

- /sources ليس سجل مصادر مستقلًا؛ هو Alias إلى SunnahPage.
- SourceDrawer يقبل source، بينما EvidenceDrawer يستخدم عقد بيانات مختلفًا باسم evidence.
- SourceDrawer يرفع status المفقود إلى verified افتراضيًا.
- إذا كانت بعض حقول المصنف أو المجموعة مفقودة، تُملأ حاليًا بأسماء عامة توحي بجهة موثقة.
- أوصاف بعض الحالات تستخدم عبارات مثل الإجماع أو اللجنة العلمية من دون أن يكون وجود تلك الجهة مثبتًا لكل سجل.
- نجاح النسخ لا ينتظر نتيجة Clipboard في بعض المسارات.
- GlobalSearchDialog يعرف أنواعًا أوسع من المادة المفهرسة فعليًا.
- بعض نتائج البحث تقود إلى صفحة عامة بدل السجل أو الفصل المحدد.
- وجود sourceUrl أو اسم كتاب لا يثبت أن كل ادعاء مرتبط به قد تمت مراجعته.

هذه ليست «تفاصيل نصية»؛ هي جزء من صدق المنتج.

## 3. طبقات المصدر

يُفصل نموذج التوثيق إلى طبقات يمكن أن توجد أو تغيب بصورة مستقلة:

| الطبقة | أمثلة |
|---|---|
| هوية المصدر | اسم المصنف، المؤلف، المجموعة، نوع المادة |
| موضع النص | كتاب، باب، رقم، جزء، صفحة، آية، فصل، حدث |
| النسخة | ناشر، طبعة، تحقيق، مخطوط، ملف رقمي |
| المادة المنقولة | النص العربي، ترجمة، مقتطف، إسناد |
| الحكم المنقول | درجة حديث، نسبة تاريخية، قراءة جغرافية |
| جهة الحكم | عالم، محقق، طبعة، Dataset، جهة تحريرية مثبتة |
| حالة المنتج | قيد المراجعة، تمت المطابقة، مختلف فيه، تقريبي |
| عدم اليقين | خلاف، نقص، تقريب مكاني، تاريخ غير محسوم |
| الوصول | رابط خارجي، ملف، معرف داخلي، رابط عميق |

غياب طبقة لا يُعالج بتأليف قيمة.

## 4. حالات المراجعة

حالة المراجعة التحريرية ليست مرادفًا لصحة الحديث، ولا لصحة النص القرآني، ولا لجودة الطبعة، ولا لاتفاق المؤرخين.

يجب أن تكون الحالات محددة المعنى. مثالها:

- تمت مطابقة السجل مع مرجع محدد.
- متعدد المصادر.
- تقريبي تاريخيًا أو مكانيًا.
- مختلف فيه.
- قيد المراجعة التحريرية.
- حالة غير معروفة.

إذا كان النظام يحتاج كلمة verified، يجب أن يعرّف بدقة **ما الذي تم التحقق منه**، وعلى أي مستوى، وأين سجل الإثبات. لا يسمح بعبارة شاملة توحي بأن كل عناصر السجل محققة.

القيمة المجهولة أو غير المدعومة تتحول إلى حالة تحفظية، لا إلى أعلى مستوى ثقة.

## 5. العزو

العزو الناتج عن المنصة يجمع فقط القيم الموجودة فعلًا. لا يضيف:

- اسم مصنف عام بدل الحقل المفقود.
- ناشرًا افتراضيًا.
- محققًا افتراضيًا.
- لجنة علمية.
- رقم صفحة غير موجود.
- وصف «طبعة معتمدة» بلا مصدر.
- وصف إجماع بلا مرجع يبرره.

إذا كانت بعض الحقول ناقصة، يمكن إخفاؤها أو عرض «غير متوفر» عند فائدة ذلك. نقص العزو معلومة، وليس عيبًا بصريًا يجب إخفاؤه.

## 6. SourceDrawer بوصفه واجهة ثقة

ترتيب الدرج المستهدف:

1. عنوان المادة والسياق الذي فتح منه المستخدم.
2. حالة موجزة ومحايدة للمراجعة.
3. النص أو المقتطف إن كان مناسبًا.
4. بيانات العزو الأساسية.
5. الحكم المنقول وجهته إن وجدا.
6. ملاحظات عدم اليقين أو الاختلاف.
7. بيانات النسخة والحقوق أو المصدر الرقمي.
8. أفعال النسخ والفتح الخارجي.
9. مسار عودة واضح إلى الموضع الأصلي.

ليس مطلوبًا عرض كل الحقول دائمًا. المطلوب ألا يتغير معنى الحقل من جناح لآخر.

في الهاتف يصبح الدرج سطح قراءة كاملًا تقريبًا، مع Scroll طبيعي ورأس غير مزدحم. يجب ألا تتنافس معه قائمة التنقل أو WelcomeModal أو BabAlsamaa أو FAB.

## 7. هجرة EvidenceDrawer

وجود مكونين للتوثيق ليس خطأ بذاته، لكن يجب ألا يكون لكل واحد منهما معنى مختلف لكلمة «مصدر».

قبل حذف أو دمج أي مكون:

- يُجرد جميع المستهلكين.
- تُقارن العقود والحقول.
- يُنشأ Adapter واضح إن لزم.
- يُنقل كل مستهلك مع اختبار فتح وإغلاق وFocus.
- لا يُستبدل اسم component فقط بينما props مختلفة.

الهدف مصدر حقيقة واحد لمفاهيم الحالة والعزو، لا مجرد ملف واحد بالقوة.

## 8. جناح /sources

عند تنفيذ خزانة مستقلة، يجب ألا تكون نسخة أخرى من صفحة الحديث. يمكن أن تحتوي:

- بحثًا في سجلات المصادر المتاحة.
- تصفية حسب نوع المادة: قرآن، حديث، سيرة، كتاب، خريطة، مادة تعليمية.
- بطاقة موجزة توضح العنوان والنوع وحالة المراجعة.
- فتح سجل المصدر بتفاصيله.
- روابط إلى جميع الادعاءات أو المواد التي تستخدم المصدر عندما تكون هذه العلاقة موجودة فعلًا.
- بيان نطاق الفهرس: ما الأنواع التي دخلت الخزانة وما الذي لم يدخل بعد.

لا تنشئ صفحة /sources قبل وجود Dataset أو فهرسة كافية لمهمتها. إذا بقي المسار Alias مؤقتًا، يجب ألا تسمي الملاحة التجربة «خزانة المصادر» وكأنها منفذة بالكامل.

## 9. البحث الجامع

البحث الجامع واجهة اكتشاف، وليس ادعاء بأن كل محتوى المؤسسة أصبح Searchable.

يجب أن يعلن نطاقه الفعلي، مثل:

- السيرة المفهرسة.
- الكتب ذات سجلات فهرس.
- الأطفال.
- الأذكار.
- القرآن إذا كان نصه مفهرسًا بالفعل.
- الحديث إذا كانت سجلاته ضمن Index.
- المصادر إذا كانت خزانة المصدر تملك Index حقيقيًا.

وجود نوع result في TypeScript لا يعني وجود بيانات لذلك النوع.

## 10. شكل نتيجة البحث

كل نتيجة تحتاج:

- عنوانًا.
- نوعًا مفهومًا.
- مقتطفًا يوضح سبب المطابقة.
- سياقًا أو مصدرًا حيث يوجد.
- وجهة دقيقة.

الوجهة الدقيقة أهم من جمال بطاقة النتيجة. إذا كانت النتيجة فصل سيرة، يفتح الفصل أو المعرف المناسب. إذا كانت آية، يفتح السورة والآية. إذا كانت مادة حديثية، يفتح السجل. وإذا لم يكن Deep Link مدعومًا، يقال ذلك أو يُنفذ قبل اعتبار البحث مكتملًا.

لا تُرسل كل نتائج السيرة إلى /seerah ثم تجعل المستخدم يبحث مرة ثانية.

## 11. روابط عميقة وحالة الرجوع

أي رابط عميق يجب أن:

- يعمل عند فتحه مباشرة.
- يعمل بعد Refresh.
- يتعامل مع معرف غير معروف.
- يحافظ على اللغة والثيم حيث يطبق المنتج ذلك.
- يسمح بالعودة إلى نتيجة البحث أو المصدر السابق.
- لا يعتمد على State مؤقت غير موجود عند فتح الرابط من الخارج.

إذا كان المنتج لا يدعم Deep Link لنوع ما، لا تُنشأ روابط تبدو دقيقة لكنها تُهمل المعرف عند التحميل.

## 12. نسخ النص والعزو

هناك أفعال مختلفة يجب تسميتها بدقة:

- نسخ النص.
- نسخ العزو.
- نسخ الرابط.
- مشاركة السجل.

كل فعل يعلن نجاحه بعد نجاح العملية. عند رفض Clipboard أو عدم توفره، تظهر رسالة فشل مفيدة.

النص المنسوخ لا يضيف صياغة دينية أو حكمًا أو اسم منصة داخل الاقتباس نفسه إلا إذا كان ذلك جزءًا واضحًا من قالب المشاركة خارج النص.

## 13. المصادر الخارجية والحقوق

الرابط الخارجي يوضح أنه انتقال خارج المنتج. يجب ألا تُستخدم روابط غير مثبتة أو Placeholder كأنها مراجع حقيقية.

عند استخدام كتب رقمية أو خرائط أو صور أو تسجيلات:

- يُحفظ المصدر.
- تُحفظ الرخصة أو شروط الاستخدام حيث يلزم.
- لا تزال نسب الخرائط.
- لا يعاد تقديم ملف غير معلوم على أنه أصل رسمي.
- لا يصبح الرابط الخارجي نفسه دليلًا على صحة الادعاء ما لم يطابق المادة المقصودة.

## 14. حالات عدم اليقين

يجب أن يكون عدم اليقين جزءًا من تصميم البيانات، لا Banner عام في أسفل الصفحة.

أمثلة:

- تاريخ تقريبي.
- موضع مختلف فيه.
- روايات متعددة.
- حكم منقول مع اختلاف.
- ترجمة غير متاحة.
- طبعة غير معلومة.
- مصدر موجود لكن العلاقة بالادعاء تحتاج مراجعة.

يمكن استخدام لون ورمز ونص، لكن لا يعتمد المعنى على اللون وحده. ويجب ألا تتحول كلمة «تقريبي» إلى قيمة أقل بصريًا لدرجة أن المستخدم لا يراها.

## 15. البحث واللغات

واجهة البحث تتبع لغة الواجهة، بينما النصوص تحتفظ باتجاهها الأصلي. نتيجة عربية داخل واجهة إنجليزية تبقى RTL في مقطعها، والعكس صحيح.

لا يوعد المستخدم ببحث صرفي أو جذري أو Transliteration إذا لم يكن النظام ينفذه. البحث البسيط ليس عيبًا إذا وُصف بصدق.

يجب اختبار العبارات الطويلة، أسماء الكتب، التشكيل، والأحرف الفرنسية والأردية حيث تدخل في الفهرس.

## 16. الإتاحة

- فتح الدرج ينقل Focus إليه بصورة سليمة.
- Escape يغلق السطح النشط فقط.
- الإغلاق يعيد Focus إلى العنصر الذي فتحه.
- نتائج البحث قابلة للتنقل بلوحة المفاتيح.
- عدد النتائج وتغيره يُعلن بطريقة لا تسبب ضوضاء لقارئ الشاشة.
- الحالة لا تعتمد على Shield أو لون.
- الروابط الخارجية لها اسم مفهوم.
- المقتطف لا يُقرأ مرتين بسبب DOM مزخرف مكرر.

## 17. الأداء

البحث يجب ألا يحمّل Corpus ثقيلًا كاملًا في أول Render بلا داعٍ. يمكن فهرسة البيانات أو تحميلها تدريجيًا وفق بنية المشروع، مع حالة Loading صريحة.

فتح SourceDrawer يجب ألا يجلب أصولًا كبيرة لا يحتاجها المستخدم. الصور والمخطوطات أو الملفات الثقيلة تُحمّل عند الطلب، مع الحفاظ على بيانات المصدر النصية حتى عند فشل الأصل.

لا تستخدم تأثيرات حركة كثيرة في نتائج البحث أو شارات الحالة. السرعة والوضوح هنا جزء من الثقة.

## 18. بوابات القبول

| المعرّف | شرط الاجتياز |
|---|---|
| SRC-01 | مصدر بلا status لا يتحول تلقائيًا إلى Verified |
| SRC-02 | الحقول المفقودة لا تُملأ بأسماء مصنفين أو محققين أو جهات وهمية |
| SRC-03 | العزو يجمع البيانات الموجودة فقط |
| SRC-04 | الحكم المنقول منفصل عن حالة مراجعة المنتج |
| SRC-05 | عدم اليقين يظهر قرب الادعاء أو السجل المناسب |
| SRC-06 | SourceDrawer يعمل على Desktop/Mobile وRTL/LTR وLight/Dark |
| SRC-07 | Focus وEscape والعودة إلى المشغل صحيحة |
| SRC-08 | النسخ يعلن النجاح بعد نجاح العملية فقط |
| SRC-09 | البحث يعلن نطاق المادة المفهرسة فعليًا |
| SRC-10 | كل نتيجة مدعومة تذهب إلى وجهتها الدقيقة |
| SRC-11 | الرابط العميق المدعوم يعمل عند الفتح المباشر وRefresh |
| SRC-12 | النتيجة الصفرية لا تدعي نفي وجود المادة خارج الفهرس |
| SRC-13 | /sources لا يسمى خزانة مستقلة مكتملة بينما هو Alias إلى SunnahPage |
| SRC-14 | الحقوق ونسب الأصول الخارجية محفوظة |
| SRC-15 | هجرة EvidenceDrawer لا تكسر المستهلكين أو عقود البيانات |
| SRC-16 | فشل مصدر أو رابط خارجي لا يمنع قراءة المادة المحلية المتاحة |

**التسليم اللاحق:** سجل أنواع المصادر، قائمة المستهلكين، عينات عزو كاملة وناقصة، Matrix للبحث والوجهات، حالات فشل Clipboard والرابط الخارجي، وصور الدرج عبر الاتجاهين والثيمين. لا تكفي شارة «شفافية مطلقة» في brand.ts لإغلاق هذا الجناح.
