## ترتيب القراءة

لمن سيقوم بالتنفيذ، لا تبدأ من وثيقة جناح منفردة وتنسى العقد العام.

**الترتيب الأدنى:**

1. اقرأ **00** كاملًا.
2. اقرأ **02** قبل تعديل أي Route أو Layout.
3. اقرأ وثيقة الجناح الذي ستعمل عليه.
4. اقرأ **09** إذا كان العمل يتعامل مع مصدر، حديث، كتاب، حدث، خريطة، أو بحث.
5. استخدم **11** لتحديد الأدلة المطلوبة قبل إعلان PASS.

## قواعد غير قابلة للتفاوض

- لا تجسيد للنبي محمد ﷺ.
- لا توليد نص ديني أو تاريخي لسد نقص البيانات.
- لا Verified افتراضي.
- لا طبعة، محقق، لجنة، إجماع، موقع، أو مسار مختلق.
- لا وصف زر بأنه يعمل دون Runtime evidence.
- لا اعتبار Build دليلًا على Visual QA.
- لا اعتبار Commit دليلًا على Push، ولا Push دليلًا على Merge.
- لا `COMPLETE` ولا `Production Ready` بلا بوابات مثبتة على SHA التسليم.

## تعريف PASS لهذه الحزمة

**PASS لوثائق المواصفة** يعني فقط:

- الملفات المطلوبة موجودة في المستودع.
- الروابط بينها متسقة.
- كل جناح أساسي له عقد.
- العقد المشترك ومصفوفة التحقق موجودان.
- لا تدعي الوثائق أنها نفذت التطبيق.

هذا **لا يساوي PASS للتطبيق**.

PASS للتطبيق يتطلب التنفيذ والاختبارات والأدلة المحددة في الوثيقة 11.

## عند بدء وكيل التنفيذ

يبدأ الوكيل بالأفعال التالية دون اختراع حالة:

- Fetch/Sync للمستودع.
- تثبيت `main` وSHA.
- جرد Routes والمكونات الحالية.
- مقارنة الوضع الحالي بالعقد.
- اختيار شريحة واحدة مترابطة.
- تنفيذها.
- اختبارها.
- حفظها في Git وفق سياسة المستودع.
- تسجيل الأدلة.
- ثم الانتقال إلى الشريحة التالية.
