# Tafsir
Primary provider: Quran Foundation `GET /content/api/v4/resources/tafsirs` to list *available resource IDs*, then `GET /content/api/v4/quran/tafsirs/{tafsir_id}?chapter_number=2&page=1&per_page=50` — **confirm exact path against the linked current reference/SDK before implementation**, since documentation labels the operation 'Get paginated tafsir records' and our research could not call it. Query supports `verse_key`, chapter/juz/page/hizb/rub filters; max 50 records. Documented record fields: `id,resource_id,verse_id,text,language_name,resource_name,verse_key,chapter_id,verse_number`; response includes `meta.tafsir_name`, nullable `author_name`, `pagination`. Source: https://api-docs.quran.foundation/docs/content_apis_versioned/4.0.0/tafsir/ .

Current `client/src/visual-golden/services/tafsir.ts` only maps the existing five bibliography entries to versions. `TafsirPage.tsx` must associate each verse with a provider resource ID, edition and review state before showing content. Do not label OpenITI text as the same edition as Quran Foundation tafsir merely by author/work name.

Hugging Face candidate `quranlab/quran-tafsir` advertises `tafsir-ibnkathir-ar` config and public dataset-server `/splits` and `/first-rows`; dataset card notes multiple upstream sources and a provenance/attribution request from Quranpedia. Use for schema exploration only pending row-level origin and rights audit. https://huggingface.co/datasets/quranlab/quran-tafsir ; https://huggingface.co/datasets/quranlab/quran-tafsir/discussions/2 . OpenITI pinned release can supply book-level commentary text, **not automatically verse-aligned**. https://github.com/OpenITI/RELEASE .
