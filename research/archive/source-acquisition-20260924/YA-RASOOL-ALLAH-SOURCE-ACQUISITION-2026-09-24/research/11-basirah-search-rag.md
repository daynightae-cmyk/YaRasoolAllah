# Basirah and global search
Current `services/basirah.ts` indexes titles/hints and local samples; `services/discovery.ts` shares this golden-shell source discovery. Extend `SearchDocument` with `domain,entityId,route,title,body,language,sourceId,versionId,availability,reviewState`; use unique `domain,entityId,language,versionId`. Quran verses 6,236 fit a client-local index, but tafsir + hadith + OpenITI require paginated server search.

Normalize Arabic for **search only**: NFC, remove U+064B..065F marks and tatweel, unify alef forms and ya/ى only in auxiliary tokens; preserve canonical Qur'an and quoted hadith bytes. PostgreSQL `pg_trgm` on normalized Arabic for typo tolerance and `tsvector` for languages with suitable configurations; Arabic morphology needs evaluation, do not claim PostgreSQL built-in Arabic stemming. Indexed `simple` config + normalized ngrams is an initial baseline. pgvector cosine/HNSW and RRF optional after keyword baseline and 30 curated relevance queries, with model/dimension recorded per embedding. https://www.postgresql.org/docs/current/pgtrgm.html ; https://www.postgresql.org/docs/current/textsearch-intro.html ; https://github.com/pgvector/pgvector .

HF candidates `Maktabati/openiti-bm25` and `Maktabati/openiti-vectors` (derivative; pin version/provenance and compare retrieval before use) https://huggingface.co/datasets/Maktabati/openiti-bm25 ; https://huggingface.co/datasets/Maktabati/openiti-vectors . No Arabic embedding model was benchmarked in this investigation; **model selection NOT VERIFIED**. Query -> ranked records -> excerpt with book/edition/page/verse/hadith refs -> optional summary constrained to cited records. Never answer as an automated fatwa. Missing evidence returns insufficient-evidence state.
